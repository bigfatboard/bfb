# Local private artifact delivery proof

`pnpm test:c11:artifact-bytes`, composed once by `pnpm test:c11`, owns this
disposable Worker/D1/R2 harness and the retained mounted artifact suites.
The frozen scope covers human upload replies, local artifact bytes and atomic grant expiry in
[private task delivery](../../docs/contracts/private-task-delivery.md).

Synthetic browser sessions use the production control routes and external
WorkspaceHub. The artifact wrapper forwards actual native R2 operations and
places independent revocation at the witnessed object/body/receipt await seams.
It is test-only tooling, not a deployed route or authority bypass. Dormant private
policy inserts are fixtures, not available private-create commands.

Six retained independently collected groups cover the upload/view controls and a
named Reviewer read recipient using a genuine synthetic cookie and CSRF token.
The restricted-project group removes only the project-access row derived from
the consumed view's canonical task/grant lineage, after actual R2 get and body
awaits. Each wave restores its synthetic project access first. Whole canonical
snapshots prove the task grant, role, epoch, parents and committed history stay
unchanged except for that independently removed project grant; FK checks remain
clean. Denied replies retain one-use consumption, receipt/audit history and R2
objects. This is not a view-parent move policy.

Four additional independently collected groups cover human upload/view grant
atomic expiry: a delayed live control and an unchanged naturally expired control
for each family. They insert explicitly synthetic historical grants before the
request, aligning two-second expired-case and five-second live-case deadlines with the native database
clock while preserving the production issuance TTL distance. Existing grants
are never rewritten; issuance TTL, credentials, authority and captured request
time do not change during the witness.

The expiry wrapper identifies the actual prepared/bound conditional consumption
UPDATE, snapshots canonical rows, witnesses a live grant immediately before the
same explicit 2,200-ms delay in both cases, and forwards the original native statements to D1 only after another
database-clock witness. Early candidate rejection or expiry before the seam is
a probe failure, not evidence of the old temporal defect. Expired requests must
return uniform 403 before upload body acceptance or view R2 reads, rolling back
consume/claim/audit rows. Separate HTTP abuse buckets remain outside canonical
snapshots. Live controls also wait until that same unchanged deadline has passed
after successful consumption, then forward actual upload body/R2 completion or
view reads; original occurrence stamps, receipts, explicit finalization and
single-use history remain intact. The two negative expectations are intended to
fail on unchanged production before its fix, not to manufacture a SQL failure.

The owning command prints bounded redacted check labels and SQL bounds measured
for artifact-handler prepared/bound statements and batch lengths, not control/Hub setup,
seam-witness or snapshot queries. Each measured statement stays within 100
bindings and 100,000 bytes. It never
persists private bodies, credentials, raw error text or local paths. Committed
receipt/consume history is retained after response denial; failed receipt batches
do not create verified records. Orphan R2 objects are not deleted.

This is local native authority and consume-statement expiry proof, not
compiled-browser presentation, live pilot, deployment, agent-upload reply,
execution, expiry at every later statement or activation certification. Cursor
compatibility and other C11 barriers remain separate. A failed OLD run is a
reproducer, not a passed certificate; the owning command reports its actual
independently collected outcomes.
